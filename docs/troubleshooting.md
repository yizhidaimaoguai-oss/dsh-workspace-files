# 排障

## 出现 SSH 密码框

本插件的 HTTP 扩展不会调用 SSH。密码框通常来自 VSCode 恢复了旧 Remote SSH 工作区，或点击了旧版 ssh-remote 链接。

1. 取消 SSH 密码框；无需为了 HTTP 文件编辑填写它。
2. 在本机运行 code --new-window，打开本地空白窗口。
3. 确认已安装 DSH HTTP Files，并刷新 DSH 页面后重新点击文件链接。
4. 已配对的目录也可在本地窗口通过“DSH: 打开已授权工作目录”打开。

外部链接进入哪个 VSCode 窗口，目前仍可能受 VSCode 的会话恢复和窗口路由影响；本版本没有宣称完全修复此问题。SSH 端口转发本身若被使用，仍需要单独保持连接。

## 浏览器点击后没有启动 VSCode

确认本机安装了 VSCode 且操作系统注册了 vscode:// 协议。允许浏览器打开外部应用。某些内嵌浏览器可能无法唤起系统应用，可改用本机浏览器访问同一 DSH 地址。

## 401、授权失效或配对链接过期

浏览器 401：通过 DSH 当前启动日志中的登录链接重新登录。

配对票据只有 60 秒有效且只能使用一次；重新点击“连接本机 VSCode”生成新的票据。桌面授权默认 30 天有效，被撤销后需要重新配对。不要分享包含 ticket 的完整链接。

## HTTP 地址被拒绝

扩展仅允许回环 HTTP 地址。直连远端域名、局域网地址或 Tailscale 地址时使用 HTTPS，也可以配置到本机回环地址的端口转发。Tailscale 网络连通与应用层授权是两件独立的事。

## 文件链接仍在服务器上打开

确认 DSH 源码补丁已经应用、client 库和 Web 前端均已重建，并重启 DSH、刷新页面。网页文件管理可用并不意味着回答链接补丁已安装。

## 保存提示冲突

另一端在当前文件读取后修改了它。先保留自己的草稿，再重新读取或比较远程内容后合并；不要把 409 当作网络错误无限重试。

## 文件无法显示或目录不完整

检查 UTF-8、2 MiB 默认文本限制、目录 2000 条上限，以及是否为符号链接或硬链接。扩展仅支持现有文本文件；网页下载可用于不支持编辑的文件类型。

## 报告问题

记录 DSH 提交、两个包的版本、操作系统、浏览器和复现步骤。提交日志前移除 Cookie、Bearer 凭据、配对 ticket、个人路径和文件内容。
